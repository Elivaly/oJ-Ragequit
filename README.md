## Сборка и запуск

    docker build -t hack:latest .
    docker run --rm -e LLM_BASE_URL -e LLM_API_KEY -e BUDGET \
      -v "$TASKS:/data/tasks:rw" --read-only --tmpfs /tmp:rw,size=2g -e HOME=/tmp \
      --cap-drop ALL --security-opt no-new-privileges --cpus 8 --memory 16g \
      --pids-limit 512 --workdir /app --entrypoint python hack:latest \
      /app/run_agent.py --tasks-dir /data/tasks

Переменные окружения: LLM_BASE_URL, LLM_API_KEY, BUDGET (по умолчанию 100000),
TASKS, OUT, TIME_LIMIT (3600), HARNESS_WORKERS (5), HARNESS_INFLIGHT (3),
HARNESS_TRACE_FILE, HARNESS_CODER / HARNESS_FAST / HARNESS_DEEP,
HARNESS_CODING_AUDIT (1).

Версии зафиксированы в requirements.txt, базовый образ python:3.11-slim.
Размер образа 1.02 ГБ, время сборки ~120 с.

## Бюджет
Бюджет читается из BUDGET. Все пороги масштабируются от него: лимит на задачу
(12% бюджета при 100 задачах, 45% при 2-5 задачах), доля на батч-триаж (4%),
остановка новых вызовов на 97% расхода. Аудит кода включается только при
запасе бюджета на задачу. Перед началом работы делается один пробный вызов
(preflight); при неверном ключе или недоступном прокси харнесс завершается
сразу, не тратя бюджет.

## Учёт токенов
Стоимость вызова = completion_tokens + prompt_tokens / 10. Токены рассуждений
считаются как выходные. Данные берутся из usage каждого ответа, кеш не
учитывается. Перед вызовом резервируется худший случай (вход/10 + max_tokens),
после — списывается факт. Отказы 429 и ошибки соединения не списывают токены.

## Оценка расхода задачи
Признаки: логарифмы длин условия/кода/тестов/данных, число файлов, тестов,
чисел в условии, категория. Базовые приоры по типам поверх которых работают
обученные веса models/estimator.json: гребневая регрессия на log(стоимость)
и логистические регрессии на вероятность успеха и выполнимость. Веса обучены
tools/train_estimator.py на собственных траекториях (188 попыток).
Дополнительно работает онлайн-калибровка по фактическому расходу.

Порядок решения: приоритет = reward * p(выполнима) * p(успех) / оценка_стоимости.
Задача не стартует, если остаток бюджета или времени меньше оценки с запасом.
Ни одна задача не отбрасывается навсегда: триаж только понижает приоритет.

## Поиск невыполнимых задач
1. Бесплатные локальные проверки: ссылки на отсутствующие файлы, пустые данные,
   отсутствие сущности в кавычках в данных, отсутствие имени в kb, деление на
   ноль в условии, отсутствие кода или тестов.
2. Батч-триаж LLM: по 18 усечённых условий в одном вызове дешёвой модели,
   не более 4% бюджета.
3. Для data_analysis/search/math модель пишет скрипт, который печатает
   INFEASIBLE, если требуемого факта нет. Исполнение локальное и бесплатное.

## Экономия токенов
По умолчанию модели без рассуждений (-noreason). Модель с рассуждениями
подключается только для дорогих задач и только после неудачи дешёвой.
Схема: один вызов -> бесплатная локальная проверка -> одна починка -> эскалация.
Арифметика (math, data_analysis) всегда считается сгенерированным Python-скриптом
локально, а не языковой моделью. Жёсткий лимит токенов на задачу, короткие
системные промпты, без агентных циклов с растущим контекстом.

## Параллельность
Не более 3 одновременных запросов (HARNESS_INFLIGHT). При ответе 429 с признаком
превышения одновременных запросов шлюз снижает потолок до 2 и далее до 1.
Ожидание берётся из Retry-After / "Limit resets at".

## Сохранение решений
После каждого решения атомарно пишется answer.txt в каталог задачи и в
workspace/ (для coding — исправленный mylib.py и answer.txt со словом DONE).
solutions.json перезаписывается после каждого решения в OUT, в каталог задач
и в /tmp; недоступные пути пропускаются.

## Траектории
trajectories/run_hard_100k.jsonl, trajectories/run_easy_100k.jsonl — по каждому
вызову модель, входные/выходные токены, стоимость, задержка, ошибка; по каждой
задаче признаки, исход, фактическая стоимость. В рантайме пишутся в
HARNESS_TRACE_FILE (по умолчанию <tasks>/trace.jsonl).

## Тренировочный набор и проверка
tools/gen_hard.py генерирует 100 задач в формате организаторов (task.json +
workspace/), 5 уровней сложности, 20% невыполнимых, слабые видимые тесты и
сильные скрытые. tools/gen_tasks.py — облегчённый вариант.
tools/grade.py проверяет прогон по видимым и скрытым тестам,
tools/diag.py показывает ожидаемый и полученный ответ.
Ключи (чистый код и скрытые тесты) пишутся рядом с набором и в контейнер
не монтируются.

## Результаты на собственном наборе
Отборочный прогон (2 задачи, бюджет 3000): 2/2, потрачено 576.
Полный набор, бюджет 100000: 66 из 80 выполнимых, потрачено 63981;
на другом seed 64 из 80, потрачено 51818.
Полный набор, бюджет 20000: 34 из 80 выполнимых, потрачено 18179 (91%).

## Ограничения среды
Контейнер read-only: все записи идут в /tmp и в смонтированный каталог задач.
Рабочий каталог процесса переносится в /tmp, логи openJiuwen направлены туда же.
Обращения к HuggingFace отключены, кеш tiktoken зашивается в образ при сборке.
В рантайме сеть не нужна, кроме обращения к LLM-прокси.
